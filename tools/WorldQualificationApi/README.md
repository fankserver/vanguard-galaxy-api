# Empty-world qualification candidate

`make package-world-qualification CONFIGURATION=Release` builds the API sources in a separate project and writes only to `artifacts/WorldQualificationApi`. The DLL retains the loader identity `VGModAPI` but carries assembly metadata `VGModAPI.WorldQualification=empty-combat-v1`. It is a replacement candidate, not an additional plugin. Do not distribute it through the normal release pipeline or install both variants.

The candidate has a hard dependency on `vgmodapi.qualification.guard` 0.1.0 so isolation initializes first. Its internal context verifier requires a numbered, unlinked Windows local-temp sandbox, armed guard, redirected save paths, matching loaded assembly locations, `Full` scenario, an unchanged authorization file, and pinned game/candidate hashes. Every context check rereads the hashes; native performance remains unmeasured. The verifier is not yet connected to admission.

The authorization file `world-qualification.authorization` is bounded to 4096 UTF-8 bytes and contains eleven lines: `vgmodapi-world-empty-v1`, exact `--vgmodapi-world-run` UUID, expiry Unix seconds (future, at most four hours), then lowercase SHA-256 hashes for the installed game assembly, API, Core, Abstractions, QualificationGuard, WorldAuthorA, WorldAuthorB and QualificationRunner. Probe files must be directly under the sandbox `game/BepInEx/plugins`. The verifier recognizes only provider IDs `vgmodapi.qualification.world.a` and `.b`. Its authenticator binds the host-recorded instance and calling assembly to the expected path and retains the native pointer; replacement or destruction refuses the context. The plugin directory must contain exactly those seven DLLs, with no other files or directories, and loaded plugin IDs must be an allowed subset of the API, guard, runner and two authors during initialization. `ParticipantsReady` separately requires both authenticated authors and binds the loaded runner instance, assembly path and native pointer before returning readiness. Once captured, runner replacement/destruction refuses the context. Admission wiring is still required. These are point-in-time observations; exclusive control of the sandbox and a complete launcher inventory remain required, not continuous filesystem integrity guarantees. A matching file does not establish that its creation or a native run was authorized.

The normal solution and `make package` do not build this project. The candidate does not currently open world admission. A package marker is not run authorization, a verified sandbox, or native qualification. `RuntimeQualified` remains false.

The empty-site environment also excludes missions eligible for native target replenishment: ordinary missions require a non-null `storyId`; native bounty/patrol/industry missions are already excluded by vanilla. This preserves the intended story TravelTo probe without invoking objective replenishment. The native replenisher's shared timer still advances normally; timer bookkeeping is not a world-content mutation guarantee. Fixtures must satisfy this restriction rather than delete or alter existing missions.

Parent-system guard regeneration permits only the inspected base no-op or `FactionSkirmish` callback. The latter iterates the POI's units, payload units and station parts, which this profile requires to be empty. Foreign overrides are refused. Deferred generation remains permitted, but both asteroid flags must be false to prevent native regeneration.

Native execution requires an independently reviewed candidate, explicit authorization, an exclusive native lease, verified game/save/profile isolation and preservation, and bounded cleanup. A restricted first profile must reject executable world state before construction and publication, preserve ordinary identity/readiness/persistence checks, and exercise public creation plus automatic restoration. Passing that profile alone does not complete the broader world milestone.
