# Loadable cargo recovery author

This BepInEx example wires the public-only [cargo library](../AuthoredDungeon/README.md) into plugin and session lifetimes. Build with `make build-dungeon-author CONFIGURATION=Release`. Output is `bin/Release/netstandard2.1/DungeonAuthor.dll`; it is not included in the API package.

Requires Mod API 0.2.7, available boarding/dungeon services on the inspected game build. Before a controlled run, set `[Content] RewardItemId` in `vgmodapi.example.cargo.cfg` to an existing game item identifier. Blank configuration deliberately registers nothing: the example does not invent asset IDs or mutate player configuration. A catalog-validation failure receives one retry at gameplay readiness; persistent failures log the item identifier and catalog diagnostic. Restart after correcting configuration.

The plugin registers the cargo definition once, subscribes before enumerating operations, and creates per-target extraction controls from fresh observations. The native panel's **Attach cargo encounter** action is an explicit opt-in; it never attaches automatically on discovery or reload, and existing attachments are not overwritten. Inspect the logged typed result. Choices use the API's authored-choice UI; their effects and occurrence state are saved by the API, not by this consumer.

The extraction action is a general contextual control for observed operations, including vanilla encounters. It acquires control only when clicked and reports conflict rather than taking over another consumer. Confirmation and crew settlement remain distinct. Settlement subscriptions remain active with the panel closed. Target helpers are disposed on target retirement or session invalidation; definition registration survives session replacement and is disposed only at plugin shutdown. Reloaded operations get fresh handles through observation. No Unity polling, native casts, Harmony patches or custom save serializer are used.

When optional panel/command/tactics/settlement integration is unavailable, the definition remains registered without contextual controls. Missing boarding/content integration or blank reward configuration prevents registration entirely and logs why.
